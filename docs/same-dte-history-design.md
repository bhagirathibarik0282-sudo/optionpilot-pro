# Same-DTE historical comparison — first stage

Status: PARTIAL. Local implementation and archive replay; not a deployed feature.

The existing RAG page already compares expiries within one recorded session. This stage adds a separate read-only historical endpoint, `/api/research/rag-same-dte-history`, accepting the existing `symbol/date/expiry/strike/side/time/asOf` fields. It does not depend on unmerged PR #714.

## Calculation and selection

The anchor and every historical comparison require two exact recorder buckets, three minutes apart. Select the same index, side, calendar DTE, IST minute and model expiry closing time. Calendar DTE is expiry date minus observation date, including weekends; it is not the continuous model time to expiry.

For each prior day, choose the verified contract minimizing the absolute difference in `10000 × (strike / observed spot − 1)` from the anchor. Ties use ascending strike then expiry. This is a transparent retrieval heuristic, not a calibrated similarity model. Return the signed difference, observed spot/premium changes, exact contract identity, quote and receipt timestamps, snapshot IDs, and model clock. Keep at most one comparison per day. No probabilities, win rates, stars or candidate verdicts are generated.

Use the existing recorded-date index and existing FULL replay reader. The HTTP wrapper reads the selected pair, then at most six prior recorded days, sequentially. It retrieves only the same three-minute window, not subsequent outcomes. Six days is an operational bound, not a sufficient statistical sample. Monthly-expiry analogues may lie outside it.

## Devil Check

- Reject missing endpoints, nonpositive prices/spot, non-TRUE recorder truth, mismatched snapshot identity, conflicting duplicate quotes, duplicate day sources, stale quotes and invalid timestamps.
- Require receipts within the bucket's first 30 seconds; allow quote timestamps up to five seconds ahead of receipt, matching the existing bounded clock-skew convention. This is a validation convention, not exchange freshness certification.
- Respect the explicit finite cutoff, capped at current time in HTTP. Historical evidence must precede the anchor day and its receipt cutoff. Same-day/future days cannot enter comparison.
- Use the effective-dated standard-session expiry resolver at each historical observation; do not apply future circular knowledge retrospectively. Different close clocks cannot match.
- Preserve missing history and source failures. Do not interpolate, backfill, write a new table, invoke an LLM, or mutate candidate/Telegram/execution authority.

## Recorded evidence

`same-dte-recorded-proof.json` was generated by `scripts/audit-same-dte-recorded.ts` using two previously captured, valid production replay JSON archives. Raw byte hashes identify both files. At 09:36 IST on September 15, NIFTY 23450 CE (DTE 0) changed by −₹1.70 over three minutes. The selected September 8 DTE-0 comparison was 23700 CE, +₹3.70, with a +5.6854 bps difference in strike/spot moneyness. These are recorded endpoint differences, not an outcome study or causal explanation. The audit stops at its first accepted example; it does not establish general coverage or accuracy.

## Remaining work

This stage has no dashboard control yet. It does not match IV, spread/liquidity, event regime, OI/PCR/walls, futures or volatility context. Those must be added with source quality and point-in-time checks before calling two days broadly similar. Special sessions and actual contract-master expiry timestamps remain unverified. No historical predictive edge has been demonstrated.

The expiry-clock sources and their primary-text audit are in `index-expiry-clock-source-audit.md`; this stage introduces no new option-pricing theory or causal claim.
